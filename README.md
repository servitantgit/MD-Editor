# MD-Editor

Редактор `.md` файлів для GitHub-репозиторію (single-file, працює прямо в браузері через Personal Access Token).

## Що нового

- **Показ зображень у прев'ю** — картинки підвантажуються через GitHub API (працює і з приватними репозиторіями), а не як прямі посилання.
- **Масштабування зображень** — наведіть курсор на картинку в прев'ю, потягніть за синій квадратик у правому нижньому куті. Розмір записується як `<img src="..." width="...">` прямо в markdown.
- **Drag & drop зображень** — перетягніть файл(и) зображень у вікно редактора (або скористайтесь кнопкою "завантажити" в тулбарі) — картинка завантажиться в `assets/` поруч із поточним файлом і вставиться в текст.
- **Drag & drop файлів між папками** — у дереві файлів зліва можна перетягнути будь-який файл (включно із зображеннями) у папку або в зону "перемістити в корінь". Усі markdown-файли репозиторію автоматично скануються, і посилання на переміщений файл переписуються на новий шлях.
- **Експорт активної сторінки в PDF** — кнопка "📄 PDF" у тулбарі редактора генерує PDF з поточного відкритого файлу (з підставленими зображеннями).

## Адаптація під конкретний репозиторій (Obsidian-подібний vault із відносними посиланнями)

- Тулза сама шукає спільну теку із зображеннями (напр. `Asset/` чи `Assets/`, або просто теку з найбільшою кількістю картинок) і саме туди зберігає нові зображення — не створює окремих `assets/` поруч із кожним файлом.
- Нові зображення й посилання вставляються у **відносному** форматі (`../../Asset/файл.jpg`) — так само, як уже написані наявні нотатки, а не в кореневому `/шлях` форматі.
- При перетягуванні файлу між папками тулза розуміє і відносні (`../x/y.png`), і кореневі (`/x/y.png`) посилання: коректно перераховує власні посилання файлу, який рухається, і виправляє всі інші `.md`-файли репозиторію, що на нього посилаються (і як на зображення, і як на звичайне посилання `[текст](шлях)`).
- Виправлено кодування шляхів для GitHub API: раніше весь шлях кодувався одним `encodeURIComponent`, через що `/` перетворювався на `%2F` — це ламало запити для файлів у вкладених папках із пробілами (а в цьому репозиторії майже всі файли саме такі, напр. `AI corrected/BOBAM/...`). Тепер кожен сегмент шляху кодується окремо, а `/` лишається роздільником.
- Дерево файлів за замовчуванням повністю згорнуте (у репо 300+ нотаток) — розгортайте потрібні розділи по кліку.

## Виправлення "картинки в прев'ю не показуються"

Причина: коли зображення ще вантажилось або не резолвилось (напр. через мережеву помилку чи неправильний шлях), воно рендерилось як **невидимий 1×1 прозорий піксель** — тобто на екрані буквально нічого не було видно, і про причину ніде не повідомлялось. Тепер:

- Поки картинка вантажиться або якщо вона не завантажилась — на її місці показується явний блок-плейсхолдер (⏳ під час завантаження, ⚠ червоним при помилці) з реальним шляхом і текстом помилки від GitHub API (наприклад, "Not Found" — означає, що обчислений шлях не збігається з фактичним).
- Якщо не завантажилась бібліотека рендерингу markdown (marked.js) — прев'ю більше не мовчить, а показує чітке повідомлення про це.
- Усі помилки додатково пишуться в консоль браузера (F12 → Console) з повним шляхом і причиною — якщо після цього оновлення щось не так, скріншот консолі дасть точну відповідь чому.

**Важливо:** у режимі звичайного редагування (сира іконка ✏️, як на скріншоті з текстом `![image](...)`) картинки і не повинні відображатись — це просто текст markdown. Щоб побачити рендер, натисніть 👁 (Preview) або ⬛ (Side by side) у тулбарі редактора.



- Автозаміна посилань опрацьовує markdown-зображення (`![]()`), markdown-посилання (`[]()`) та сирі `<img>` теги. Посилання у форматі `onenote:...` та інші зовнішні схеми (http/https) свідомо не чіпаються.
- Дуже екзотичні вручну написані посилання (наприклад, із символами, які самі по собі ламають синтаксис markdown, як-от `(` чи `)` прямо в імені файлу без екранування) можуть не розпізнатися регулярним виразом — це обмеження самого markdown, а не тільки цієї тулзи.
- Відповідно до `agent.md` цього репозиторію: тулза сама нічого не переписує без вашої явної дії — усі зміни (збереження, вставка картинки, переміщення файлу) відбуваються тільки по кліку/перетягуванню, які виконуєте особисто ви.
- Функціонал перевірявся вручну на коректність коду (JS-синтаксис, HTML-структура) і логіку резолву шляхів на реальних іменах файлів із цього репозиторію, але **не був протестований проти живого GitHub API** в цьому середовищі (немає мережевого доступу з токеном). Перед довірою до масового переміщення файлів варто спершу прогнати сценарій на одному-двох тестових файлах: відкрити → вставити картинку → змінити розмір → перемістити в іншу папку → перевірити, що посилання в інших нотатках і справді оновились → експортувати PDF.
