# Future — ідеї і плани

## Вход без введення токена: OAuth-логін через GitHub

**Проблема/фіча:** зараз користувач мусить сам генерно и вставляти Personal Access
Token (PAT) у екрані входу. Хочется, щоб можно було «увійти через аккаунт GitHub»
і получить підтвердженния (у т.ч. 2FA на телефон), не вставляя токен руками.

**Ключевое обмеження (важно, зрозуміли в дискусіи 2026-09-25):**
GitHub OAuth **не підтримує PKCE** и вимагає `client_secret` при обміні `code` на
`access_token`. Секрет **неможна сховати в чистому клиентському JS** (DevTools все
читає). Тому чисто на GitHub Pages — надійно нельзя, трєба **мінімальний бекенд**,
який тримає секрет и віддає клієнту готовий токен.

**Механіка «підтвердження на телефон»:** якщо у користувача увімкнута 2FA, GitHub
сам запросить підтвердженние (SMS/authenticator/app) на своїй сторінці — додаткових
дій з нашого коду не треба. Це стандартний OAuth-поток.

### Варіанти реалізації
1. **OAuth App + міні-Node бекенд** — споразмірній повноцінный «Увійти через GitHub».
   Один сервер тримає `client_id`/`client_secret`; ендпойнти `/auth/start` і `/auth/callback`.
2. **Serverless-функції (Vercel / Netlify / CF Workers)** — той же прокси без отдельного
   сервера; клієнт залишається статичним.
3. **OAuth Device Flow + серверний прокси** — GitHub показує короткий код і
   `github.com/login/device`; користувач вводить код на компі/телці і підтвердоює.
   Финальний обмін `device_code` на токен все-одно вимагає secret → нужен прокси.
4. **Гібрид** — залишити PAT як запасний варіант и додати OAuth поверх.
5. GitHub Apps — тоже вимагає секрет на сервері, для чистої двустного сценария не простее.

### Що трэба буде змінити в коді (черновик)
- `js/app.js` `readSession/onLoginClick` — додати OAuth-гілку (крiм вставленного PAT).
- `js/github-client.js` — поки палиться на `Authorization: Bearer <token>`; для OAuth
  можна просто передавати токен, що повернуть бекенд.
- `index.html` — в екрані логіна додати кнопку «Увійти через GitHub» и пояснення.
- `serve.mjs` — на локальном сервері теж можно додати прокси-обмін для дебага.
